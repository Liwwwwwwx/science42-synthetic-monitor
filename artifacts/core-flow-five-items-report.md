1. 平台登录；
2. 消息发送；
3. 流式回答；
4. 结果返回；
5. 页面持续“生成中”。

测试环境：`http://192.168.0.112:23191`  
聊天入口：`/#/chat`  
案例入口：`/#/cases`  
执行工具：Playwright、Chromium、k6。  
执行日期：2026-07-27。

本报告不包含服务器 CPU/内存/磁盘监控，也不包含团队接口专项监控。

## 3. 测试准备

### 3.1 工具

- Playwright：控制浏览器、填写输入框、发送问题、等待页面回答、刷新页面、保存截图/视频/Trace；
- k6：本次用于站点可用性基线，不直接判断页面流式状态；
- Windows 任务计划程序：用于后续按固定周期启动核心流程监控；
- `monitor/core-flow-monitor.mjs`：用于登录、发送、回答和 75 秒超时监控。

### 3.2 登录状态

首次登录通过一次性脚本完成：

```powershell
$env:SCIENCE42_BASE_URL='http://192.168.0.112:23191'
$env:SCIENCE42_ENTRY_PATH='/#/cases'
$env:SCIENCE42_CHAT_PATH='/#/chat'
$env:SCIENCE42_USER='测试账号'
$env:SCIENCE42_PASSWORD='测试密码'
npm run auth:setup
```

脚本打开浏览器后，由测试人员完成拖拽验证码和登录，并保存：

```text
playwright/.auth/science42.json
```

密码没有写入报告或测试脚本。

## 4. 项目一：平台登录

### 测试目标

确认平台能够打开登录窗口，账号密码可以提交，验证码完成后能够进入平台，并且保存的登录状态能被后续自动化脚本使用。

### 测试方法

1. Playwright 打开 `/#/cases`；
2. 检查手机号/邮箱输入框、密码框、协议复选框和登录按钮；
3. 填写测试账号和密码；
4. 人工完成拖拽验证码；
5. 点击登录；
6. 保存 Playwright `storageState`；
7. 使用该状态运行 S-10、S-30A、S-30B 和 SR-30；
8. 另外运行核心流程定时监控，检查登录状态是否失效。

### 使用命令

```powershell
npm run auth:setup
$env:SCIENCE42_STORAGE_STATE="$PWD\playwright\.auth\science42.json"
npm run test:s10
```

### 结果

- 首次人工登录成功；
- 保存状态后可以支持 S-10、S-30A、S-30B 和 SR-30；
- 后续核心监控试跑时，页面重新出现登录框和拖拽验证码；
- 监控记录为“登录状态失效或未提供有效 storageState”。

### 结论

一次性登录通过，长期登录监控未通过。当前账号状态不能作为无人值守监控的长期认证方式。

### 建议

- 提供可续期 Token；
- 提供专用监控账号；
- 或提供不需要人工验证码的服务账号登录接口；
- 监控发现登录框时应立即产生 P1 告警。

## 5. 项目二：消息发送

### 测试目标

确认用户输入问题后能够成功发送，任务不会卡在发送前，页面能显示本次用户消息，并且连续发送不会导致发送按钮失效。

### 测试方法

Playwright 每次：

1. 定位聊天输入框；
2. 填入固定题目；
3. 按 Enter 发送；
4. 等待页面出现对应回答；
5. 记录 HTTP 状态、首字时间、完整时间和页面状态。

执行批次：

```powershell
npm run test:s10
npx playwright test playwright/s10.spec.mjs --repeat-each=3 --workers=1
npm run test:s30b
```

### 结果

| 批次 | 结果 |
|---|---:|
| S-10 | 10/10 完成 |
| S-30A | 30/30 完成 |
| S-30B | 同一会话连续 30 次，30/30 HTTP 200 |

### 结论

消息发送正常链路通过。测试期间未观察到发送无响应、发送按钮失效或新增消息完全不显示。

## 6. 项目三：流式回答

### 测试目标

确认发送后页面能够出现回答内容，并且回答不是长时间没有任何首字或一直停留在加载状态。

### 测试方法

Playwright 脚本在发送后：

1. 等待页面回答节点出现；
2. 记录从发送到首段有效文本出现的时间；
3. 观察回答是否继续生成；
4. 判断页面是否进入完成、失败或超时状态；
5. 通过截图和 Trace 保留异常现场。

相关脚本：

```text
playwright/helpers.mjs
monitor/core-flow-monitor.mjs
```

### 结果

- S-10、S-30A、S-30B 正常发送后均能收到页面回答；
- 正常链路中未发现页面长期没有首字；
- 未出现可确认的流式连接断开；
- 尚未执行 NW-SHORT/NW-LONG，因此没有验证断网后流式重连行为。

### 结论

正常流式链路基础通过，但流式中断、重连、断网恢复尚未完成专项验收，不能宣称流式可靠性已达长期目标。

## 7. 项目四：结果返回

### 测试目标

确认任务最终能够返回明确结果，而不是只有中间状态；刷新页面后，已经完成的结果仍然能够恢复。

### 测试方法

1. 发送固定问题；
2. 等待页面显示回答；
3. 判断是否出现明确回答、失败或超时状态；
4. 完成后等待保存；
5. 刷新页面；
6. 检查原会话和结果是否仍存在。

执行命令：

```powershell
npm run test:sr30
```

### 结果

- S-10：10/10 有明确结果；
- S-30A：30/30 有明确结果；
- S-30B：30/30 请求返回 HTTP 200；
- SR-30 smoke：刷新后原会话可恢复；
- 正常测试中未发现 75 秒后仍无结果的任务。

### 结论

正常任务结果返回和一次刷新恢复通过。

## 8. 项目五：页面一直“生成中”

### 测试目标

发现任务超过 75 秒仍没有完成、失败或超时状态，或者流式连接结束后页面仍持续显示“生成中”。

### 正常链路判定

核心监控脚本使用以下规则：

- 最长等待时间：75 秒；
- 出现本次唯一问题对应的回答：视为有结果；
- 页面尾部仍包含“生成中”或 `Generating`：判定异常；
- 页面尾部包含失败/超时：判定明确失败；
- 75 秒内没有本次问题对应回答：判定超时。

运行命令：

```powershell
$env:SCIENCE42_MONITOR_URL='http://192.168.0.112:23191'
$env:SCIENCE42_STORAGE_STATE="$PWD\playwright\.auth\science42.json"
$env:MAX_TASK_MS='75000'
npm run monitor:core
```

### 结果

- S-10、S-30A、S-30B 正常测试没有发现持续“生成中”；
- 没有发现 75 秒未完成的正常任务；
- 核心监控试跑未进入回答判断阶段，因为先发现登录状态失效；
- 尚未执行 NW-SHORT/NW-LONG，无法验证流式中断后是否会一直“生成中”。

### 结论

正常网络、正常登录条件下未发现该问题，但异常网络专项尚未完成，当前只能标记为“未发现，不等于已完全排除”。
