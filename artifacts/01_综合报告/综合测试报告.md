# Science42 自动化测试与监控项目综合报告

**测试环境：**`http://192.168.0.112:23191`  
**API 文档：**`http://192.168.0.112:1120/api/docs`  
**测试范围：**平台登录、消息发送、流式回答、结果返回、会话保存恢复、团队接口探活、研发案例目录和 HTTP 可用性

## 1. 项目目标

本项目围绕平台核心流程及团队接口测试，建立可重复执行的自动化测试和监控能力，及时发现登录失败、消息发送无响应、流式回答超时、页面长时间“生成中”、空响应、5xx/504、团队接口不可用和团队输出异常等问题，并保留完整证据，支持后续整改和复测。

## 2. 工具和实施方式

| 工具 | 用途 |
|---|---|
| Playwright + Chromium | 登录、聊天发送、回答采集、会话刷新恢复、案例目录检查、截图和 Trace |
| Node.js | 执行自动化脚本、接口探活、JSON 结果汇总 |
| k6 | HTTP 探活、错误率、P95 响应时间 |
| Toxiproxy | 预留用于延迟、断流和代理异常注入 |
| Promptfoo / DeepEval | 预留用于回答格式、相关性和质量评估 |

核心链路：

```text
登录 → 进入聊天 → 发送问题 → 接收流式回答 → 判断生成结束
     → 校验返回内容 → 保存会话 → 刷新 → 验证恢复
```

每条测试问题使用唯一标识，记录问题、实际返回文本、耗时、状态、HTTP 信息和证据路径；团队接口脚本默认只读，不执行创建、修改、加入、踢人或删除操作。

## 3. 自动化工程和命令

安装：

```powershell

npm install
npx playwright install chromium
```

配置：

```powershell
$env:SCIENCE42_BASE_URL='http://192.168.0.112:23191'
$env:SCIENCE42_ENTRY_PATH='/#/cases'
$env:SCIENCE42_CHAT_PATH='/#/chat'
$env:SCIENCE42_STORAGE_STATE="$PWD\playwright\.auth\science42.json"
$env:MAX_TASK_MS='75000'
```

执行命令：

```powershell
npm run auth:setup
npm run test:s10
npm run test:s30b
npm run capture:responses
npm run test:sr30
npm run test:core-regression
npm run test:case-catalog
npm run probe:team-api
k6 run .\k6\site-smoke.js -e BASE_URL=http://192.168.0.112:23191 -e ITERATIONS=10 -e INTERVAL_SECONDS=1
```

核心源码位于：`playwright/`、`api/`、`monitor/`、`k6/` 和 `config/`。

## 4. 平台核心流程测试结果

### 4.1 登录

- 已验证登录页、测试账号输入、滑块验证和登录成功后的案例/聊天入口。
- 自动化曾捕获到登录态失效提示：“登录已过期，请重新登录”。
- 登录态失效截图和 Trace 已保存，可用于监控和问题定位。

### 4.2 消息发送和返回

已执行精确计算、严格 JSON、固定列表、长文本、短格式和多轮上下文等场景。主要结果如下：

| 场景 | 实际结果 | 状态 |
|---|---|---|
| 大整数计算 | 出现正确结果 `121932631112635269`，但同时返回推理过程和重复结果 | 格式失败 |
| 严格 JSON | 返回 `{"name":"Zhang San","age":18}` | 通过 |
| 三点列表 | 返回上一条 JSON 残片 `":"Zhang San","age":18}` | 内容失败 |
| HTTP 504 长文本 | 正确说明网关超时、客户端超时区别并给出两项排查步骤 | 通过 |
| 上下文第一轮 | 返回 `ACK` | 通过 |
| 上下文第二轮 | 正确恢复 `ORANGE-42`，但带有额外解释 | 部分通过 |

主要缺陷：严格输出约束不稳定，连续请求之间出现回答串台或流式残片污染，不能只依据 HTTP 200 判断业务成功。

### 4.3 会话保存和恢复

完成上下文测试后刷新聊天页面，约 7311 ms 后输入框、第二轮问题和 `ORANGE-42` 均恢复，判定为通过。

### 4.4 历史返回内容

历史固定问题采集共 10 条，其中 8 条捕获到内容，2 条在脚本 75 秒窗口内未捕获对应回答；历史页面还出现过：

```json
{"error":true,"message":"empty response"}
```

该结果说明必须同时检查正文非空、最终完成状态和内容关联，不能只检查页面或 HTTP 状态。

## 5. 团队接口测试结果

### 5.1 接口范围

API 文档确认团队接口主要分为：

- `/api/v1/group/*`：团队计划、个人团队列表、用户团队列表、申请状态、成员信息等。
- `/api/v1/groupconv/*`：团队会话、团队消息、搜索、统计、收藏和历史记录等。

### 5.2 只读探活

已对 6 个只读接口执行探活：团队计划、个人团队列表、用户团队列表、申请状态、收藏会话和收藏消息。

- 结果：6/6 返回 HTTP 401 `Not authenticated`
- 超时：0
- 5xx/504：0
- 结论：接口路由可达，认证拦截生效；由于未注入登录令牌，不能将该结果作为登录后业务可用性结论。

### 5.3 当前阻塞

按 OpenAPI 的 `UnifiedLoginRequest` 尝试调用 `POST /api/v1/user/login`，当前地址返回 404；正式站点地址同样不是该 API 路由。因此登录后团队接口测试需要平台侧提供正确登录 API、专用 Token/Cookie、测试 `group_id`、会话 ID 和团队输出预期值。

## 8. 已发现问题

| 编号 | 问题 | 影响 | 状态 |
|---|---|---|---|
| CORE-001 | 严格输出约束不稳定 | 只输出数字/代码词时出现额外解释 | 待整改 |
| CORE-002 | 连续回答出现 JSON 残片串台 | 结果内容错误，影响业务可信度 | 待重点定位 |
| CORE-003 | 出现 `empty response` | 页面可能显示空回答或错误结果 | 待结合服务端日志定位 |
| CORE-004 | 登录态失效 | 监控请求无法正常执行 | 已能检测，待完善自动恢复告警 |
| ENV-001 | 历史会话 100/100 | 新建会话测试受阻 | 待提供专用账号/清理策略 |
| API-001 | OpenAPI 登录地址返回 404 | 无法获取团队接口认证令牌 | 待平台确认真实地址 |
| CASE-001 | 案例页没有运行入口 | 无法完成案例批量运行和结果核对 | 待平台补充执行入口 |
